# Changelog

## 2026-10-19 — 多商品采集间隔与来源限制保护（v1.1.8）

- 新增 `XHS_SOURCE_MIN_GAP_SECONDS`（默认 120s，最小 60s，最大 3600s），规定同一获准来源的**上一个商品访问完成后**才开始计算下一个商品的最小间隔。
- SQLite 持久化来源冷却时间，事务内原子领取任务、限制同一来源同时在途任务，Worker 重启/多实例不重置速率控制。
- 401/403/429、验证码及来源主机阻断暂停整条来源并取消待执行任务，避免其余商品继续请求受限来源；只有人工重新确认许可并保存启用设置，才能恢复 `blocked` 绑定。
- 不修改站点请求指纹、不绕过限制、不声称降低频率即取得平台许可；单商品监控周期仍按原规则执行。
- 增加速率配置、SQLite 跨商品间隔/暂停/手动恢复测试，`.env.example` 与 Docker Compose 同步配置。


## 2026-10-19 — 来源授权表单失败原因可见（v1.1.7）

- 明确“已经核实许可”仅 6 字符，启用来源时需至少 12 字符且必须是真实许可依据。原接口拒绝保存但表单底部不提示失败，造成勾选后仍等待来源授权的误解。
- 前端就地显示输入长度、缺失权限与 CSS 字段检查、保存失败原因；后端返回可读的 `details`，同时保留兼容性错误码。
- 不会替用户开启任何权限，不会将填写字符串误认为真实授权；新增验证测试，保留禁用来源草稿保存能力。


## 2026-10-19 — 等待来源授权状态修复（v1.1.6）

- 后台展示数据源未启用、许可未核实、授权过期和 CSS 字段缺失等具体原因，并提供跳转「数据源与设置」的入口。
- Worker 定时扫描自动修复**权限已核实且启用**但仍留在 `awaiting_authorization` 的旧商品绑定；禁用来源时不会绕过任何授权开关。
- `scripts/check-sales.py` 增加只读来源开关、许可依据是否填写及等待原因的诊断输出（不泄露授权原文）。
- 新增状态诊断单元测试与授权恢复/去重任务回归测试；实际 VPS 上的许可情况尚未取得，不会直接自动开启数据源。


## 2026-10-19 — 店铺口碑、销量和粉丝历史监控（v1.1.5）

- 从用户提供的商品详情 HTML 区分商品级 `已售431` 与店铺级 `已售426`、`粉丝数 1261`、`卖家口碑 4.32`、店铺名称。
- Playwright 读取店铺名称和口碑，按标签而不是相同 CSS 类的第一个元素辨识店铺已售与粉丝数。
- SQLite 新增 8 个快照字段（口碑原文/百分位、店铺销量原文/数值/精度、粉丝原文/数值/精度），旧库以串行幂等的加性迁移保留全部历史。
- 商品列表与详情历史显示各项店铺数据，来源设置新增店铺评分和统计信息选择器。
- 增加数值解析、字段防混淆、数据库迁移与 Chromium 本地 DOM 烟测；另将快照写入提取为可测试的数据访问函数，新增真实 SQLite 写入/幂等/缺失值回归测试，不将静态 HTML 当作真实定时任务结果。


## 2026-10-19 — Ubuntu 08:00 自动更新部署（v1.1.4）

- 新增 `scripts/auto-update.sh`、`deploy/systemd/xhs-monitor-auto-update.service` 与 `.timer`：每日北京时间 08:00 自动检查 GitHub main 分支，有新版本则部署；无变更则跳过重启。
- `scripts/deploy.sh` 增加 `schedule`、`schedule-status`、`unschedule`，首次成功部署自动安装计划任务；`update` 与自动任务使用同一进程锁。
- 更新分为预构建+临时数据库单元测试+Chromium 烟测、在线 SQLite 备份、启动并等待健康检查三个阶段；禁止覆盖本地修改或强制重置 Git。
- 日志和成功 SHA 记录在 root 目录/systemd journal；服务器重启导致错过触发时自动补执行。
- 部署定时任务不代表“自动采集竞品销量”；实际授权/数据源/生产部署仍须分别验证。

## 2026-10-18 — goods-detail 链接兼容与隐私修复（v1.1.2）

- 核实用户提供的 `goods-detail` 链接可由 URL 路径解析 24 位商品 ID，不能把分享参数里的嵌套 `itemId` 误当作该商品 ID。
- 添加商品时只保存去除全部 query/fragment 的标准链接，避免 `xsec_token`、`instation_link`、`share_id` 被保存为商品数据。
- 同一商品的多个分享链接采用商品 ID 去重，兼容已入库的旧版带参链接，重复添加时可原位清理。
- API 添加接口不再回传原始带追踪参数 URL；增加相应自动化回归测试。
- 真实商品名称、价格和销量尚未能经网页或授权 API 确认，不应宣称已成功采集。
